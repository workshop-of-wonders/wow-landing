## Key decisions & conventions

- **Escala tipográfica móvil (≤720px)**: 30 display · 27 cierre · 24 H2 · 19 H3 · 16 texto · 15 texto de tarjeta · 12 eyebrow. No inventar tamaños intermedios; ver el bloque "Mobile type scale" al final de `styles.css`.
- **El home no se toca (2026-10-06)**: `index.html` está aprobado como "perfecto" por la dueña y es la referencia visual del resto del sitio. No modificarlo (ni su CSS propio, ni sus secciones, ni sus enlaces) a menos que ella lo pida explícitamente. Las páginas internas se adaptan al lenguaje del home, nunca al revés. Ojo con los estilos compartidos de `styles.css`: cualquier regla nueva debe ir con prefijos propios (`.sp-*`, `.of-*`, `.hv-*`) y no alterar las del home (comprobado hasta ahora: `git diff main -- index.html` vacío).
- **Naming de marca (2026-09-26)**: solo **Wonder · Optimize · Win** y los dos Labs (**Brand & Experience Lab**, **Insight Lab**). CREA / CRECE / DEFINE - Core Lab están retirados — no volver a usarlos en copy, etiquetas ni código.
- **Fuente EfectoWow**: si se reemplaza `design-system/fonts/EfectoWow-Regular.ttf`, correr `python3 scripts/fix-font-metrics.py --fix` (requiere `pip install fonttools`) y subir el `?v=` de los `@font-face` (styles.css, admin/index.html, pronto/pronto.css, index-alt.html). Sin eso las mayúsculas con tilde (É, Ñ…) quedan pegadas a la letra siguiente.
- **Breakpoints**: `1200px` = Proceso circle / pinned Nosotros on (below it both are plain stacked, driven by `mobileTimelineQuery` in main.js — keep CSS and JS in sync). `900px` is the main mobile/tablet cutoff used across the site (hero, labs accordion, nav). `720px` and `560px` are used for a few finer adjustments. When adding a new mobile override, check whether JS logic (e.g. `window.innerWidth` gates) needs to match the same breakpoint as the CSS — this caused a bug once (see 2026-08-08, labs accordion).
- **`--page-x`**: `clamp(24px, 6vw, 96px)` — the horizontal section padding variable. Use this instead of a fixed px value for any new section's left/right padding so it scales with viewport width.
- **Falling icons (contact section)**: Matter.js physics playground. Known-sensitive settings: `restitution: 0.9` + default solver iterations (bouncy, piles up — client's preferred feel, don't "fix" the piling/clumping without asking, it's intentional). Drag release is hardened across `mouseup/touchend/touchcancel/pointerup/blur`. If you ever call `Render.setPixelRatio` again, remember to also set `mouse.pixelRatio` to the same value (and re-set it on resize) — Matter's `Mouse` module doesn't pick this up automatically, and drag silently breaks on any scaled/HiDPI display without it.
- **`flex-basis` on axis-flip bug**: watch out — properties like `flex: 0 1 520px` written for a *row* layout become a fixed **height** if that flex container switches to `flex-direction: column` at a breakpoint (e.g. hero-content, hero-media, lightbox-desc all hit this). Always re-check/reset `flex-basis` inside mobile media queries after adding a fixed basis for desktop.
- **Hub diagram connector lines**: drawn dynamically in JS (`hubArrows` SVG) from real pill positions, not hardcoded paths — recalculates on resize/font-load.
- **Case-study modal**: dark bottom bar (name, category, description, tags) + an editorial image collage on top, built by `ProjectCollage` (see below). Triggered by `[data-lightbox]` on both work-items and client-logos.
- **`ProjectCollage`** (defined inline in `index.html`'s bottom `<script>`, styled in `styles.css` under `.project-collage`/`.pc-item`): a generic, reusable "automatic editorial collage" — give it any array of image URLs (or `{src, priority}` objects) and it measures each image's real aspect ratio, builds a fixed 2-row CSS grid (`grid-auto-flow: column dense`) that grows horizontally with `overflow-x: auto`, and sets each item's pixel width from its own ratio at the row height (`--pc-row-h`) — never `object-fit: cover`, never cropped/stretched. A handful of portrait or high-`priority` images get promoted to "tall" (`.pc-span2`, spans both rows) to vary the rhythm; the browser's dense packing fills the rest with no per-project logic or hardcoded positions. Any `[data-lightbox]` element can opt into a real, curated set via `data-images='["a.png", {"src":"b.png","priority":2}]'`; without it, the modal falls back to the project's single `data-img` plus 3 images seeded from the shared `hero-photos` pool (legacy behavior, unchanged). No project (Epika, Otto, or otherwise) has a bespoke layout — this replaces a dead/never-finished `lightboxImg1-4` implementation that referenced DOM elements no longer in the markup.
- **Project form modal**: triggered by any `[data-open-form]` element (nav "Hablemos", hero CTA, services CTA, contact pill, hub "W" click).
